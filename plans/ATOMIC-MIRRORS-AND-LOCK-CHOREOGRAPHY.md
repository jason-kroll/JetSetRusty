# PLAN: remove the atomic mirrors and the drop-lock choreography

Task: eliminate the two reentrancy workarounds around `GAME_STATE.miner`:

1. **The atomic mirrors.** `Miner.air`/`Miner.jump` live under
   `Mutex<Miner>`, but `level_get_tile_type` (levels.rs:5072) needs them for
   `tile_type_for` (levels.rs:5035: SolidFloor becomes Solid only when
   `air == 1 && jump == 0`) and its callers in miner.rs already hold the
   miner lock. std `Mutex` is not reentrant, so miner.rs hand-syncs
   `GAME_STATE.miner_air`/`miner_jump` at 12 write sites (miner.rs:174-175,
   251, 485-486, 525, 543, 547, 578, 597, 603, 677 — counted by grep). Two sources of truth,
   kept in sync by convention. Worse, they are **already stale in some
   windows**: game.rs:430,454,465 (`game_change_level` repositioning),
   rope.rs:280, and replay.rs:247 (`set miner`) write `miner.air` without
   updating the mirror, so `level_get_tile_type` reads stale values there.
   The C original reads `minerWilly.air` live.
2. **The drop-lock choreography.** ~16 `drop(miner)` calls, scoped blocks
   (game.rs:438-441), and one `try_lock` (game.rs:579-581), all enforcing by
   comment the rule "never hold a guard across a call that locks the same
   field" (`game_change_level` from miner.rs ×5, `miner_save` inside
   `game_init_room`, `rope_tick`/`rope_draw`). A violation is a *silent*
   freeze — non-reentrant mutex deadlocks with no panic.

Fix: pass the data explicitly instead of re-reading globals under a held
lock. `level_get_tile_type(tile, air, jump)` takes the values as parameters
(closures at the probe call sites capture `miner.air`/`miner.jump`); the
atomics and all sync stores are deleted. Boundary functions
(`game_change_level`, `game_init_room`, `miner_save`/`miner_restore`,
`miner_ticker`/`miner_drawer`, `rope_tick`/`rope_draw`, `game_got_item`)
take `&mut Miner`/`&Miner` from a single lock held at the top of the
ticker/drawer, so the borrow checker enforces the no-reentrancy rule at
compile time instead of ~16 `drop()`s enforcing it at runtime.

**What does NOT change:** `GAME_STATE` stays a `static LazyLock` with
`Mutex`/atomic fields — not because the audio thread reads it (it doesn't;
`audio.rs` never references `GAME_STATE`, the SDL callback uses
`AUDIO_STATE`), but because `cargo test` runs unit tests on parallel
threads against the shared static, so the fields must stay `Sync`. The
`Mutex`es stay; only the *reentrancy hazards* go away.

Hard constraints: phase 2 is behaviour-preserving — all 24 golden
replays byte-identical, never `UPDATE_GOLDEN=1` for it. **Phase 1 is
explicitly a behavior fix** and so is **phase 3**: the single-lock pass
resurrects `game_got_item`'s dead pan write — the always-failing
`try_lock`'s only call site is the item-pickup scan, which holds the
miner lock, so `set_audio_pan_x(miner.x)` has never fired and the Item
SFX's pan has not followed Willy to pickups since the try_lock landed
(C writes `audioPanX = minerWilly.x` live, per pickup; the port's other
live writer is the death path, die_init). With the copy threaded under
the held guard the write resumes, the mix changes from the pickup frame
onward (`channel_pan(ch, audio_pan_x())` per sample), and the
**item-picking scenarios' audio hashes move** — verified at the tree:
`conveyors`, `play`, `victory` fail; the other 21 pass (no pickup
anywhere else — harm's spike path crosses no item tile, the sweeps'
random walks miss). Removing the mirrors makes
`level_get_tile_type` see the live `air`/`jump` (C parity) in the windows
where the mirrors are currently stale (game.rs:430/454/465, rope.rs:280,
replay.rs:247). Run `cargo test` first without updating anything: inspect
every divergent frame with
`cargo run -- --replay tests/scenarios/<name>.txt --dump <frame> /tmp/f.ppm`,
confirm each divergence is a stale-mirror read (expected in `transitions`,
`rope`, and `sweep-*` where `set miner` runs — for the sweeps: the poke
zeroes `air` with C parity, but the mirror keeps the *pre-poke* value, so
mid-air pokes make the `Land` probe's `air == 1 && jump == 0` test read a
different SolidFloor verdict than C; dump the poke frame and one landing
frame per divergent sweep room), and only then
`UPDATE_GOLDEN=1 cargo test --test replay` with the frame analysis in the
commit message. If no golden diverges, phase 1 is a pure refactor and no
update happens. Gates after every phase: `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings`, `cargo test`, `cargo build`.
Do not push; one commit per phase, imperative mood, no type prefix, with
the `Generated by Mistral Vibe.` / `Co-Authored-By: Mistral Vibe
<vibe@mistral.ai>` trailer.

## Phase 2 — `&mut Miner` through the room-change boundary (pure refactor)

- `miner_save(miner: &Miner)` / `miner_restore(miner: &mut Miner)` take the
  miner; MINER_STORE stays thread-local.
- `game_init_room(miner: &mut Miner)` — takes the miner instead of calling
  `miner_save()` (which locked). The **three** call sites lock once:
  the two in `dispatch.rs` (`Pending::ReinitRoom`, `GamePhase::Init`) and
  `game_change_level`'s direct call (game.rs:481) — thread the param through
  that third site too: today change_level holds the guard while a fresh
  `game_init_room()` re-locks, the same silent freeze this plan kills;
  leaving the third site unrewritten reintroduces it one call deep.
  `let mut m = GAME_STATE.miner.lock().unwrap(); game_init_room(&mut m);`
- `game_change_level(dir, miner: &mut Miner)` — the internal lock and the
  scoped block (game.rs:438-476) go away; the five miner.rs call sites
  (396, 425, 515, 564, 617) drop their `drop(miner)` and pass `&mut miner`.
- game.rs unit tests (`change_level_above_guard`) lock and pass `&mut`.
- Goldens byte-identical.

## Phase 3 — single lock per ticker/drawer pass (behavior fix — C parity)

- `do_game_ticker` locks miner once and passes `&mut` to `miner_ticker`,
  `rope_tick`, and — through it — `game_got_item`: the item-pickup scan
  calls it (miner.rs:662), two calls inside `do_game_ticker`, *not* directly.
  `game_got_item` reads only the miner's x (the SFX pan); thread it as
  `game_got_item(pan_x: i32)` by copy, not a guard or `&mut Miner` — the
  `try_lock` at game.rs:579-581 disappears either way and the
  `&mut`-at-two-depths param threading is unnecessary. (The Maria-mode

- `do_miner_ticker` keeps its single top-level lock; internal `drop(miner)`

  callee now takes the param (game_change_level from phase 2); drops before
  calls that do *not* lock miner (move_left_right, audio) can also go —

## Risks

- Phase 1 golden divergence: must be justified frame-by-frame as C parity
  (live `minerWilly.air`), never blanket-updated. The likely divergent
  scenarios are `transitions` (Above guard at game.rs:430), `rope`
  (rope.rs:280), and sweeps using `set miner` (replay.rs:247).
- Phase 2/3 borrow-checker fights where a closure and a `&mut` alias the
  same guard — resolve by capturing copies (`let air = miner.air;`) at
  the probe call sites rather than borrowing through the closure.
- **Phase 3's resurrected pan write**: the always-failing `try_lock` was a
  dead write (the port's C-parity bug, filed when it landed), not lock
  plumbing — "lock granularity is invisible single-threaded" is true for
  granularity, but *resurrecting a write is visible in the goldens*. The
  item-picking scenarios' audio hashes move (`conveyors`, `play`,
  `victory`); justify each divergent frame as C parity (the C's live pan,
  the only other writer being die_init), never blanket-updated; the 21
  others pass throughout.
- Lock granularity changes are invisible single-threaded, but keep the
  lock scope identical to today (one lock at the top of each pass) so the
  diff stays mechanical.
