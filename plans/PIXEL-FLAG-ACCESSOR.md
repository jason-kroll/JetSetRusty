# PLAN: un-duplicate `B_WILLY` behind a typed pixel accessor

Task: `src/rope.rs:188` re-declares `const B_WILLY: i32 = 4;` — a
type-divergent duplicate of `src/video.rs:12`'s `const B_WILLY: u8 = 4;` —
forced by `video_get_pixel(&Pixel) -> i32` (video.rs:280-282) leaking the
private `Pixel.point` bitfield as a raw i32. That function has exactly one
caller: rope.rs:216's Willy-collision probe, `(pixel_val & B_WILLY) != 0`
(rope.rs:218). Replace the raw getter with a typed predicate so the flag
constant lives in exactly one place and `Pixel`'s fields stay private.

## Phase 1 — code

- video.rs: delete `video_get_pixel` (:280-282); add in its place
  `pub(crate) fn video_pixel_has_willy(pixel: &Pixel) -> bool { pixel.point & B_WILLY != 0 }`
  — `B_LEVEL`/`B_ROBOT`/`B_WILLY` (:10-12) stay private to video.rs.
- rope.rs: delete `const B_WILLY: i32 = 4;` (:188) and its stray
  "// Level constants" comment; the import at :5 swaps `video_get_pixel` for
  `video_pixel_has_willy`; the probe (:216-218) becomes:
  `if willy_rope_zero && video_pixel_has_willy(&pixels[buf_index(pos)]) {`
- Behavior identical (same bit test on the same byte); the `rope` replay
  scenario exercises this path, so goldens pin it. Byte-identical expected.
