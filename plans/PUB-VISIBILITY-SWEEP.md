# PLAN: sweep `pub` to `pub(crate)` and deny `unreachable_pub`

Task: the crate is a **binary** — `src/main.rs` declares every module as a
private `mod`, and `tests/replay.rs` drives the game through
`CARGO_BIN_EXE_jetsetrusty` subprocesses, so nothing ever imports the crate
as a library. Every `pub` item is therefore unreachable from outside the
crate: 195 `pub` tokens across the 15 of the 20 `src/*.rs` files that contain
any (93 `pub fn`, 41 item declarations — consts, enums, structs, statics —
and 61 `pub` struct fields). `src/dispatch.rs` already follows the honest convention
(`pub(crate)` on all 16 of its items); the rest of the crate still carries the
C-era `pub` from when the modules were compiled as separate C ABI units.
Make visibility truthful and compiler-enforced.

## Phase 1 — the sweep + the ratchet

- Sweep every item-position `pub ` in `src/*.rs` to `pub(crate) ` — 195 sites,
  one token per line, e.g.
  `perl -pi -e 's/^(\s*)pub (?!crate\b)/$1pub(crate) /' $(grep -rlP '^\s*pub (?!crate)' src/)`
  then **read the full diff** before staging. Verification afterwards:
  `grep -rPn '^\s*pub (?!crate)' src/ | wc -l` must be 0, and the
  belt-and-braces `grep -rn '\bpub \b' src/ | grep -v 'pub(crate)'` must also
  be empty (catches anything not at line position).
  (This covers `pub fn`, `pub const`, `pub enum`, `pub struct` + its `pub`
  fields, `pub static`, `pub const fn`. No strings or comments match the
  anchored pattern; the diff review is the real check.)
- `Cargo.toml`: add the ratchet so no future `pub` can sneak back in:

  ```toml
  [lints.rust]
  unreachable_pub = "deny"
  ```

  Verified empirically: in a bin crate, rustc's `unreachable_pub` hard-errors
  on `pub fn`/`pub struct`/`pub enum`/`pub const`/`pub static`/`pub mod` in
  non-root modules; it does **not** lint `pub` fields (a field's effective
  visibility is capped by its type's), so the `grep == 0` check above is the
  only field backstop. Today's `clippy -D warnings` does not catch these (the
  lint is opt-in), which is why the `[lints.rust]` table is required.
- Delete the vestigial `#![warn(unused_unsafe)]` at `src/game.rs:1` — the crate
  contains zero `unsafe` (grep-verified), so the attribute is dead config.
  Lint configuration now lives in exactly one place: `Cargo.toml [lints]`.
- Visibility does not reach codegen, so goldens are untouched **by
  construction** — but `cargo test` still runs to prove it (53 unit + 24
  replay, byte-identical).

## Risks

- The sweep must be **total**, including `pub` struct fields (61 of them, e.g.
  `Miner`'s `pub x: i32` at game.rs:105-113) and `pub static GAME_STATE` /
  `VIDEO_PIXEL` / `VIDEO_COLOUR`. `unreachable_pub` lints items, **not
  fields** — the mandatory `grep -rPn` == 0 check is the sole field backstop
  (it is total: every `pub` in src/ is at line start; no multi-pub lines, no
  `pub use`/`pub(super)` re-exports, and the three `levels.rs` macros expand
  to private expressions). The lint is the item backstop; the grep is the
  field backstop.
- The lint only sees non-root modules; `main.rs` must stay pub-free — it
  currently declares only private `mod`s (main.rs:1-20), so nothing to do,
  just don't add any.
- All cross-module paths are `crate::…`, which `pub(crate)` satisfies; no
  `use` resolution changes, so clippy/fmt should be unaffected. If the sweep
  exposes anything (it should not), fix mechanically and say so in the commit.
- `pub const fn tile_2_pixel` (video.rs:19) becomes `pub(crate) const fn` —
  fine; it is only called in-crate.
