# PLAN: small-idioms bundle — flash flag, joystick state, replay exit code

Task: three small "C in Rust" leftovers in `src/game_main.rs`/`src/replay.rs`,
bundled because each is a one-file, behavior-preserving change:

1. **`VIDEO_FLASH: Cell<i32>` → `Cell<bool>`.** The flash flag is XOR'd at one
   site (`toggle_video_flash(timer_update(timer_flash))`, game_main.rs:344)
   with `timer_flash` configured `timer_set(&mut timer_flash, 25,
   TICKRATE * 8)` (game_main.rs:687, replay.rs:210) → divisor 480, `rate = 0`,
   so `timer_update` (misc.rs:133-140) returns only 0 or 1. The i32 provably
   holds {0,1} — a de-facto bool. Callers use it truthily
   (`video_flash() -> bool`, game_main.rs:137) except two array indexers
   (`tile.paper[video_flash() as usize]`, levels.rs:5012-5013).
2. **`JOY_STATE: Cell<[bool; 3]>` → a struct.** Indexed bool array
   (game_main.rs:163, read at :209-219 as `s.get()[0]` etc.). Becomes
   `JoyState { left, right, fire }`; `map_joy_event` (game_main.rs:236) and
   its unit tests (:844-893 — `joy_axis_threshold_is_pinned` and
   `joy_buttons_and_axis_preserve_the_other_channels`) switch from arrays to
   the struct. Replay-immune:
   the SDL event loop never runs there, so the state stays all-false.
3. **Replay exit path → `ExitCode`.** `replay::main(args) -> i32`
   (replay.rs:175, returning 0/1/2) is consumed by
   `std::process::exit(crate::replay::main(&args[2..]))` (game_main.rs:549)
   while `main.rs` is `fn main() { game_main::run(); }`. Restructure to
   `main() -> ExitCode` → `run() -> ExitCode` → `replay::main() -> ExitCode`,
   returning instead of exiting (runs TLS destructors — strictly better;
   exit codes 0/1/2 preserved exactly for the test harness).

## Phase 1 — flash flag to bool

- game_main.rs:128: `Cell<i32>` / `Cell::new(0)` → `Cell<bool>` / `Cell::new(false)`.
- game_main.rs:137-138: `video_flash()` body becomes `VIDEO_FLASH.with(|c| c.get())`.
- game_main.rs:140-141: `toggle_video_flash(bit: i32)` → `toggle_video_flash(flip: bool)`, body `c.set(c.get() ^ flip)`.
- game_main.rs:344: `toggle_video_flash(timer_update(timer_flash) != 0)`.
  Record the invariant in a comment here (and at the replay copy of the
  `timer_set` call): `timer_flash` must keep `rate == 0` (divisor 480,
  remainder 25) so `timer_update` returns only 0/1 and `!= 0` is an exact
  bool — a future rate > 0 config would silently corrupt a bool.
- levels.rs:5012-5013: `video_flash() as usize` → `usize::from(video_flash())`.
- Behavior identical (0/1 ⇔ false/true); the loader flash runs in every
  replay, so goldens exercise this. Byte-identical expected.

## Risks

- Phase 1's invariant: the bool conversion is only exact because
  `timer_flash.rate == 0`. The comment pins it; goldens cover the flash in
  every replay.
- Phase 3: `ExitCode::from(2)`/`from(1)` must keep the exact codes the
  harness sees today (`std::process::exit(2)` ≡ `ExitCode::from(2)`).
  Returning from `main` (instead of `process::exit`) runs destructors; replay
  mode has no SDL/audio threads to disturb, and stdout is flushed at scope
  exit regardless.
- Phase 2: `map_joy_event`'s unit tests construct state arrays — mechanical
  literal swap to struct; no logic change.
