# PLAN2: unit-test the `game_change_level(Above)` guard

Task: pin the one gameplay path the golden scenarios can't reach (it needs
sub-tile x precision mid-climb) with a unit test. **No game-code changes** —
one new test module in `src/game.rs`, one commit. Do not push.

## The guard under test

`src/game.rs:412-432`, `game_change_level(dir)`: on `Direction::Above` it
computes `target = level_dir(Above)` = the current room's `map[0]`; if

```rust
(target == THEDRIVE && 22 < miner.x < 32) || (target == FIRSTLANDING && miner.x > 182)
```

it sets `miner.air = 2` and returns **without** changing room. Otherwise it
stores the new level, repositions Willy (`y=104`, `x=(tile&31)*8`, `air=0`, …)
and calls `game_init_room()` — which is headless-safe (only in-memory locks;
replay's `set level` already exercises it every run).

Reference facts (verified):

- `Direction` enum at `src/game.rs:86`: `Above=0, Right=1, Below=2, Left=3`;
  each room's `LevelData.map` in `src/levels.rs` is `[above, right, below, left]`.
- above→THEDRIVE(4): level **45** ("Under the Drive"). above→FIRSTLANDING(28):
  level **22** ("Main Stairway"). First Landing (28) above→34 (Top Landing).
- Constants `THEDRIVE`, `FIRSTLANDING`, `GAME_STATE`, `Direction` all live in
  `src/game.rs`.

## What to write

Append to the bottom of `src/game.rs`:

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use std::sync::atomic::Ordering::Relaxed;

    #[test]
    fn change_level_above_guard() {
        let game = &*GAME_STATE;
        let above = Direction::Above as i32;

        // Set current room + Willy's x (tile kept consistent). Drops the
        // miner lock before returning — never hold it across game_change_level.
        let setup = |level: i32, x: i32| {
            game.level.store(level, Relaxed);
            let mut m = game.miner.lock().unwrap();
            m.x = x;
            m.y = 104;
            m.tile = 13 * 32 + (x / 8);
            m.air = 0;
        };

        // Guarded: entering The Drive from below with 22 < x < 32 is blocked.
        setup(45, 25);
        game_change_level(above);
        assert_eq!(game.level.load(Relaxed), 45);
        assert_eq!(game.miner.lock().unwrap().air, 2);

        // Guarded: entering First Landing from below with x > 182 is blocked.
        setup(22, 200);
        game_change_level(above);
        assert_eq!(game.level.load(Relaxed), 22);
        assert_eq!(game.miner.lock().unwrap().air, 2);

        // Boundaries are strict: x == 22 and x == 182 are NOT blocked.
        setup(45, 22);
        game_change_level(above);
        assert_eq!(game.level.load(Relaxed), THEDRIVE); // 4
        assert_eq!(game.miner.lock().unwrap().y, 104);   // Above branch repositions

        setup(22, 182);
        game_change_level(above);
        assert_eq!(game.level.load(Relaxed), FIRSTLANDING); // 28

        // Unguarded plain Above transition: First Landing (28) -> Top Landing (34).
        setup(28, 40);
        game_change_level(above);
        assert_eq!(game.level.load(Relaxed), 34);
    }
}
```

## Pitfalls

- All cases in ONE `#[test]` fn: cargo runs tests on parallel threads and
  `GAME_STATE` is global, so two tests mutating it would race. No other unit
  test touches `GAME_STATE` (the rest are pure), so this stays safe.
- Re-`setup(...)` before every case — a successful transition changes `level`.
- `game_change_level` locks `miner` internally and drops it before
  `game_init_room` (which re-locks via `miner_save`). Never hold the `miner`
  guard across the call.
- Assert `air == 2` only on the blocked path; the allowed path sets `air = 0`.
