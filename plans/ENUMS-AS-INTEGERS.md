# ENUMS-AS-INTEGERS: replace the C-era "enums are ints" casts with typed enums

Task: convert the ~100 sites that treat a Rust enum as a raw integer (the
review's issue #1) so that enum values travel the code as enum values.
**Behaviour-preserving refactor only**: every existing golden must pass
*unchanged* — never run `UPDATE_GOLDEN=1` under this plan. If any test fails
at any point, stop, revert that commit, and report. Do not push; commit
locally, one commit per phase, imperative mood, no type prefix, with the
`Generated by Mistral Vibe.` / `Co-Authored-By: Mistral Vibe <vibe@mistral.ai>`
trailer. Gates after every phase: `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings`, `cargo test`.

### The C original's layout (reference/c-original/src/common.h, main.c)

- `enum KEY`: `KEY_LEFT..KEY_RSHIFT` = 0..5, `KEY_1..KEY_0` = 6..15,
  `KEY_A..KEY_Z` = 16..41, `KEY_ESCAPE` = 42, `KEY_PAUSE` = 43,
  `KEY_MUTE` = 44, `KEY_QUIT` = 45, `KEY_ELSE` = 46, `KEY_NONE` = 47.
- `sdlKey[36]`: `[LEFT, RIGHT, SPACE, RETURN, LSHIFT, RSHIFT, _1.._0,
  a..t]`, indexed *by KEY value* for held-key polling. Letters u..z have no
  table entry — polling `KEY_U` would read past the array in C (latent UB in
  upstream; nothing calls it).
- `MapKeycode`: digits 1–4 → `KEY_1 + (sym - SDLK_1)`; the letters
  `e i p r t w y` → `KEY_A + (sym - SDLK_a)`; everything else → `KEY_ELSE`.
- Cheat level select scans `System_IsKey(KEY_1 + i)` for `i` in 0..30 —
  i.e. table slots 6..35: digits 1..0 plus letters a..t.

### The Rust divergence (important, discovered while verifying)

Rust's `Key` was renumbered: only `K1..K4` exist (6..9), letters are produced
arithmetically as `Key::A as i32 + offset` with **A = 10** (letters = 10..35),
and `Escape` is pinned at 36 (no K5..K0, no Quit variant). The
`SDL_KEYS`/`SDL_SCANCODES` tables, however, are exact copies of C's 36-entry
layout: slots 10..15 hold `_5.._0` and 16..35 hold `a..t`.

Why the numbers diverged: the Rust `Key` was declared with only the
variants that can ever arrive as one-shot `gameInput` — `map_keycode`
never produces digit inputs 5..0 (they map to `Key::Else`), so `K5..K0`
were omitted and `A` landed directly after `K4` at value 10, sliding
every letter six slots below its C position. C's enum declares all ten
digits and all 26 letters first, putting letters at 16..41. The
divergence is an accident of declaring a leaner enum, not a semantic
choice.

Consequence: a Rust letter *value* is not the letter's own table slot
(`'w'` → value 32 → `SDL_KEYS[32]` = keycode `q`). This is harmless today —
verified call-site by call-site: every `system_is_key` argument is either in
the aligned 0..9 range (movement, jump, enter, shifts, K1..K4) or is the
cheat scan's `Key::K1 as i32 + i`, which (like C's) is table-index arithmetic
over slots 6..35 and never treats its argument as a letter input. Nothing
polls a letter `gameInput` value. But the numbers only line up by accident,
which is exactly the kind of fragility this plan removes: adopting C's
numbering makes value == table slot for every pollable key.

Safety of renumbering: `gameInput` values are responder-only — they never
enter the video/audio output, replay holds raw SDL symcodes (`map_keycode`
runs on them each frame either way), and goldens cover the cheat, pause,
mute, and escape paths. As long as the sym → key → letter/level round trips
are preserved, shifting internal values is hash-invisible.

### Other verified facts

- `GameMode` derives `Debug, Clone, Copy, PartialEq` (no `Ordering`); its
  discriminant order `Normal < Maria < Running < Toilet` matches the C
  `GM_*` enum, so a derived `PartialOrd` reproduces every `<`/`>=` exactly.
- Nothing outside the main thread ever touches `GAME_STATE.mode` (the audio
  thread only locks `AUDIO_STATE` / `AUDIO_MUSIC_PLAYING`), so typed
  accessors on the existing `AtomicU8` change no concurrency contract.
  The GameState storage model itself is a *separate* cleanup (issue #3).
- `TileType` derives `Debug, Clone, Copy, PartialEq, Eq`; the C port's
  `t as i32 > TileType::Space as i32` probes are pure discriminant-order
  queries (see also plans/PHYSICS-UNIT-TESTS.md).
- `replay.rs` `set mode` accepts only the four names, so every store of
  mode is a valid discriminant by construction.
- `SFX_ITEM..SFX_ARROW` (audio.rs, `usize`) double as `SFX_PITCH` row
  indices and as values cast to `i32` for `audio_sfx`, which casts back and
  matches the consts. `MUSIC_SCORE` is indexed by the same `MUS_*` values.

## Design

D1 — `GameMode`: keep the `AtomicU8`; add typed accessors on `GameState`:

```rust
impl GameMode {
    fn from_u8(v: u8) -> GameMode { match v { 0..=3 => ..., _ => unreachable!(...) } }
}
impl GameState {
    pub fn mode(&self) -> GameMode { GameMode::from_u8(self.mode.load(Relaxed)) }
    pub fn set_mode(&self, m: GameMode) { self.mode.store(m as u8, Relaxed) }
}
```

Field `mode` becomes private to `game.rs` (the `LazyLock` init is in-module,
so this compiles; it also locks out future raw stores). Derive `Eq` +
`PartialOrd`. Comparison sites become `game.mode() >= GameMode::Running`.
Replay's `SetOp::Mode(GameMode)` parses names straight to the enum and calls
`set_mode`. `from_u8` on an invalid byte is `unreachable!` — the port's
fail-loud precedent (the `robots.rs` gfx `expect`); with every store going
through `set_mode`, the arm can fire only if the one-writer contract is
bypassed, and then you want to know, loudly. A silent clamp to `Normal`
was considered and rejected: a bad byte would surface as subtly wrong
gameplay (Maria never starts, the toilet never flushes) instead of a
pointed crash. If release-crash-resilience is ever wanted, switch to
`debug_assert!` + clamp — review and the goldens run in debug, so the
loud failure still guards every refactoring path. The fossilised "How to
use enums in Atomics" comment block that used to live here in `GameState`
was removed in the plan-review commit (`from_repr` recipe, never used
by any code).

D2 — `TileType`: derive `PartialOrd` (and `Eq`) in levels.rs; the two
`ground_check` sites become `t0 <= TileType::Space || t1 <= TileType::Space`
and the matching `>` pair. Ordering is used nowhere else on `TileType`.

D3 — `Key`: expand to the C enum faithfully.
  - Disciminants: `Left..RShift` 0..5 (unchanged), add `K5..K0` = 10..15,
    `A..Z` = 16..41 as real variants, `Escape` = 42, `Pause`, `Mute`,
    `Else`, `None` (no `Quit`; the port has no quit key). Every discriminant
    equals the C original's from here on.
  - `game_input` slot becomes `Cell<Key>`; `map_keycode(sym: i32) -> Key`
    maps the seven letters via a const `[(Keycode, Key); 7]` table and digits
    1–4 via `Key::K1 + offset` style arithmetic kept inside one function;
    callers stop passing i32.
  - `system_is_key(key: Key)` — the `as usize` table lookup exists in exactly
    one place (game_main.rs), with a doc comment stating that only
    `Key::Left..=Key::T` (0..35) are pollable, mirroring C's 36-entry table.
  - The cheat level-select scan iterates a const `[Key; 30]`
    `[K1..K0, A..T]` (same key set C's `KEY_1 + i` scan covers).
  - `Key::letter(self) -> Option<u8>` (range pattern `Key::A..=Key::Z` plus
    offset inside the one method) and `Key::from_letter(u8)`
    replace cheat.rs's `letter_byte(input: i32)` arithmetic; the cheat
    tests build keys with `Key::from_letter`.
  - DELETE `Key::from_key_code` and its LOW/HIGH const tables: with the
    slot typed, `game.rs`/`title.rs` match `game_input()` directly on
    variants, and codes.rs matches `Key::K1` instead of the `KEY_1: i32`
    consts (those consts are deleted too).
  - Add a pin test, `key_discriminants_match_the_c_original`, asserting
    `A=16, K5=10, T=35, Z=41, Escape=42, None=46`, so the `SDL_KEYS`
    value==slot coupling cannot be silently broken. Extend the map_keycode
    tests to the new pins.
D4 — `Sfx` and `MusicScore` enums (optional phase, see questions):
  `audio_sfx(Sfx)`, `audio_music(MusicScore, bool)`; `SfxInfo::pitch_table:
  Sfx`; `SFX_PITCH`/`MUSIC_SCORE` indexing via `as usize` confined inside
  audio.rs; the three per-file `MUS_*` consts and the five `SFX_* as i32`
  casts disappear.

## Risks and guardrails

- Discriminant drift is the one real hazard: SDL_KEYS/SDL_SCANCODES are
  value-indexed. The pin test in 3a makes drift fail loudly in `cargo test`
  before any golden run.
- `unreachable!` in `GameMode::from_u8` is a debug-session landmine only if
  some future code stores a raw byte; the field going private is what
  prevents that. (Alternative considered: clamp to `Normal`, rejected as
  silent-wrong.)
- Performance is a non-issue: `mode()` adds a 4-arm match per read
  (~15 reads/frame); `Key` is `Copy`.
- Behaviour parity bugs (e.g. C's out-of-bounds poll for KEY_U..Z, the
  current letter-slot quirk) are to be *recorded*, not fixed, under this
  plan. After 3a the quirk is gone as a side effect of correct numbering —
  that is a representational fix, not a behavioural one (nothing polled
  the affected paths).

## Explicit non-goals

- GameState's atomic/mutex storage model (issue #3) — `mode` stays an
  `AtomicU8`; only the API around it becomes typed.
- The `miner_air`/`miner_jump` shadow caches (issue #2).
- The `Event = Option<fn()>` dispatcher.
- `miner.dir`'s `D_RIGHT/D_LEFT` int consts and `update_dir`'s `dir += 1 /
  dir += 2` flag accumulation (same disease, but gameplay-logic-level;
  propose separately if wanted).
- `codes.rs`'s internal `self.key: i32` digit state.
- The `direction` enum array-index in `level_dir` (`map[dir as usize]`):
  left as-is; it is a single, deliberate table lookup. (If desired, a
  four-arm match would remove the cast — cosmetic.)

## Decisions (review round 1, 2026-11-17)

1. `GameMode::from_u8` on an invalid byte: `unreachable!` (rationale in
   D1). Clamp rejected as silent corruption; `debug_assert!` + clamp is
   recorded in D1 as the release-resilience alternative should that
   policy be wanted later.
2. `Key` numbering: adopt the C numbering (D3). The divergence is an
   accident of a leaner enum (see Verified facts); the C layout restores
   value == table slot and line-for-line parity with `common.h`.
3. Phase 4 (`Sfx`/`MusicScore`): in scope.
4. The "how to use enums in Atomics" guidance turned out to live in the
   `GameState` comment block in `src/game.rs` (added in `ceef7ed`, the
   getter/setter era — a `from_repr` sketch no code followed), not in
   AGENTS.md; AGENTS.md's GAME_STATE section remains accurate and is
   untouched. The comment block was removed in this plan's review
   commit.
