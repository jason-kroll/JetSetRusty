# ROOM-SWEEP-GOLDENS: one seeded fuzz golden per room (levels 0-59)

Task: add a room-sweep of fuzz golden replay scenarios — one per level, so
every room's tile layout, guardians, ropes and conveyors run through the
physics/rendering under seeded random input. **Scenarios, tests, goldens and
docs only — do not change game code.** If a sweep replay panics or any
existing test fails, **stop and report**; do not fix or re-bless anything in
this plan. Do not push.

## Verified facts (read first)

Scenario format (header comment in `src/replay.rs`; examples in
`tests/scenarios/`). `#` starts a comment, full-line or trailing:

```
frames 500               # total frames (required)
seed 7                   # game RNG seed (optional, default 1)
100 space                # press Space at frame 100, held 1 frame
414 left 18              # press Left at frame 414, held 18 frames
340 set level 28         # set item_count|level|lives N, set mode ..., set miner X Y
```

Key names: `a-z`, `0-9`, `left`, `right`, `space`, `enter`, `lshift`,
`rshift`, `escape`, `tab`, `pause`, `lalt`, `ralt`. Overlapping holds are
fine (fuzz.txt has them).

- Boot sequence used by every gameplay scenario:
  `100 space` (skip code card), `300 enter` (start game in The Bathroom, 33).
- `set level N` (`src/replay.rs`, `SetOp::Level`): places Willy at the left
  edge (`miner.x = 0`, `miner.tile &= !31`), stores the level and queues
  `game_init_room` as the next ticker — the room fully re-inits (robots, rope,
  drawing). Existing scenarios put it at frame 340, after boot. **Do the same;
  never before frame 300** (the loader/title own the ticker then).
- `set lives 9` makes deaths respawn instead of reaching game-over. If lives
  do run out, the replay ends early (`game_running()` breaks the loop) and the
  golden simply has fewer lines — still deterministic. Use 9, not 99:
  single-digit lives rendering in the status bar is the proven path.
- Levels are **0..=59**: `LEVEL_DATA: [LevelData; 60]` in `src/levels.rs` is
  indexed directly by `GAME_STATE.level` (`ACTIVE_LEVELS[level as usize]`),
  level 0 = The Off Licence, and ROOMS.md's No. column is 0-based (33 = The
  Bathroom = `THEBATHROOM`, 59 = The Bow is the last). `set level 60` would
  panic with index-out-of-bounds — never emit it.
- Each replay runs in its own process (`tests/replay.rs::replay()` spawns
  `jetsetrusty --replay <file>` and **asserts exit status** — a panic in game
  code fails the test, which is exactly the crash detection we want).
- Goldens: `check(name)` replays `tests/scenarios/<name>.txt` and compares
  against `tests/golden/<name>.hashes` line by line; regenerate with
  `UPDATE_GOLDEN=1 cargo test -q --test replay`. Goldens pin current behavior,
  bugs included — only regenerate after verifying the output is correct.
- Runtime: the 22 current replay tests take ~1.7s total; 60 x 500 frames adds
  only a few seconds. CI is fine with this.

## Steps

### 1. Write the generator: `scripts/gen_sweep.py`

```python
#!/usr/bin/env python3
"""Generate tests/scenarios/sweep-NN.txt: one fuzz scenario per level (0-59).

Deterministic: fixed seed, explicit output lines. The generated .txt files are
committed and are what the tests run — this script is documentation only,
never invoked by CI, build.rs, or the test suite. Re-running it must produce
byte-identical files.
"""
import random
from pathlib import Path

OUT = Path(__file__).resolve().parent.parent / "tests" / "scenarios"
SEED = 20261117
FRAMES = 500
KEYS = ["left", "right", "space"]

def main():
    for level in range(0, 60):
        rng = random.Random(SEED + level)
        lines = [
            f"# Room-sweep fuzz: level {level} (see ROOMS.md), seeded random input.",
            "# Generated by scripts/gen_sweep.py — do not edit by hand.",
            f"frames {FRAMES}",
            f"seed {level}",
            "100 space          # skip the code card",
            "300 enter          # start the game (The Bathroom, level 33)",
            f"340 set level {level}   # enter room {level} from the left edge",
            "360 set lives 9    # deaths respawn instead of game-over",
        ]
        for f in range(400, FRAMES):
            if rng.random() < 0.6:
                lines.append(f"{f} {rng.choice(KEYS)} {rng.randint(1, 8)}")
        path = OUT / f"sweep-{level:02}.txt"
        path.write_text("\n".join(lines) + "\n")

if __name__ == "__main__":
    main()
```

Run it: `python3 scripts/gen_sweep.py` — then `git status --short` must show
exactly 60 new files `tests/scenarios/sweep-00.txt` .. `sweep-59.txt` plus the
script. Re-run it once and confirm `git status` is unchanged (byte-identical
regeneration).

### 2. Register the sweep in `tests/replay.rs`

Add after the `fuzz()` test in the "Golden scenarios" section:

```rust
// One seeded fuzz scenario per level: sweep-00 .. sweep-59.
#[test]
fn sweep() {
    for level in 0..=59 {
        check(&format!("sweep-{level:02}"));
    }
}
```

One test fn on purpose (not 60): `check()` already spawns a process per
scenario, and a loop keeps the failure message pointing at the exact file.

### 3. Spot-check before generating goldens

```sh
cargo run -q -- --replay tests/scenarios/sweep-18.txt --dump 450 /tmp/s18.ppm
python3 /tmp/render.py /tmp/s18.ppm 4   # /tmp/render.py is in plans/REMAINING-GOLDEN-GAPS.md section 2a
```

sweep-18 is On the Roof (a rope room): the dump at frame 450 must show the
room's layout, not the title screen — proves `set level` fired and the room
loaded. Also check a golden-less run's stdout line count:
`cargo run -q -- --replay tests/scenarios/sweep-33.txt | wc -l` should be
close to 500 (fewer only if lives ran out).

### 4. Generate goldens, then verify

```sh
UPDATE_GOLDEN=1 cargo test -q --test replay sweep   # writes tests/golden/sweep-NN.hashes
cargo test -q --test replay sweep                   # must pass
wc -l tests/golden/sweep-*.hashes | tail -1         # ~60 files, most with ~500 lines
cargo test                                          # full suite: unit + all replay goldens
cargo clippy --all-targets -- -D warnings
cargo fmt --check                                   # replay.rs is Rust; run cargo fmt if it fails
```

## Pitfalls / stop rules

- **Generator determinism**: fixed `SEED`, explicit lines only — no timestamps,
  no dict-ordering dependence. The committed .txt files are authoritative.
- Never wire the generator into `build.rs`, CI, or the tests.
- `set level` at frame 340, never earlier; `set lives 9` at 360 (after the
  `300 enter` game reset, which itself resets lives).
- Early-ended goldens (lives exhausted → game over → title → `game_running()`
  false) are valid; don't "fix" them by extending frames.
- **If any `sweep-*` replay exits non-zero**, a game-code path panicked in
  that room — stop, report the level and frame, and compare against
  `reference/c-original` (buildable with `make` there) before anyone
  regenerates goldens.
- **If any pre-existing test fails at any point**, stop immediately and report
  (same rule as the previous plan).
- No changes to `src/` game logic, no changes to existing scenarios/goldens.
